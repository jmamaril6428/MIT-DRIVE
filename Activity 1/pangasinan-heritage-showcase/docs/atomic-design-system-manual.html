Purpose

This manual enables a new developer to build consistent heritage pages using the supplied tokens, HTML/CSS components and documented parent-width rules. It includes all five atoms, three molecules and two organisms named in the assignment. Each entry contains a real rendered preview, usage context, responsive behaviour and a reusable HTML/CSS extract.

Full code lives in template/; full-resolution PNGs live in docs/previews/. The PDF scales previews to fit the page. Open template/index.html after extracting the ZIP for interactive examples.

The student should review, personalize and understand it before submission. No student identity, test score, visitor rating or institutional endorsement has been invented.

1. System foundations

1.1 Atomic Design as a mental model

Brad Frost's model describes atoms, molecules, organisms, templates and pages. This library implements the first three levels required by the brief; the final section shows page composition. It is a reusable hierarchy, not a requirement to build in a rigid linear order. [1]

LevelComponents in this libraryResponsibility
AtomsButton; Typography; Colour Tokens; Icon; ImageFoundational appearance and single controls.
MoleculesHeritage Card; Search Form; Navigation ItemA small, purposeful grouping of atoms.
OrganismsHeritage Grid; Header NavigationA complete page region assembled from smaller parts.

1.2 Install by composition

<link rel="stylesheet" href="styles/tokens.css">
<link rel="stylesheet" href="styles/base.css">
<link rel="stylesheet" href="styles/components.css">
<script src="demo.js" defer></script>

Use this order: tokens define values; base defines document defaults and utilities; components define reusable classes. previews/preview.css frames test cases only and is not a production dependency. demo.js supplies the demonstration search, adjustable grid and menu disclosure.

1.3 Design decisions

Sea teal expresses the coastal context; heritage gold provides emphasis. A serif display stack adds editorial character, while a system sans-serif stack keeps body text familiar and avoids remote font downloads. Colour ramps are primitives; product components normally use semantic aliases such as --color-primary. A few internal demonstration styles use ramp values directly.

Use 4px-based spacing, 6–22px corner radii and modest shadows. Typography uses fluid clamp() values; the fluid part uses viewport units. Explicit parent-width heading changes still apply inside .type-prose. Do not confuse viewport-fluid type with a container query.

1.4 Correct container-query ownership

A size query styles a descendant according to an ancestor's size. A component cannot query its own width and use that same query to restyle itself. Therefore .card-container, .search-container, .grid-container and .header-container are real wrappers; do not remove them. [2]

.card-container { container: card / inline-size; }
/* Query the wrapper; change its descendant. */
@container card (min-width:32rem) {
  .heritage-card { display:grid; }
}

All rem-to-pixel examples assume the default 16px root size. Keep rem units in source so thresholds adapt with user settings. Browsers without container queries retain the stacked baseline; no JavaScript layout polyfill is required by this library.

Accessibility rules

Target WCAG 2.1 AA: preserve labels, useful image alternatives, keyboard operation, visible focus, logical headings, status messages and meaningful link text. Body text needs 4.5:1 contrast; qualifying large text and essential non-text controls need 3:1. Decorative card boundaries need not serve as interactive control boundaries. [3]

Atom 01

Button

Usage: use a real button for an action and a link styled as a button for navigation. Primary identifies the main action; secondary supports it; danger is reserved for destructive actions. Preview “book” labels illustrate styling only; no booking service is implemented.

Responsive logic: parent named action-bar, ≤26rem: all non-inline buttons expand to full width. Above 26rem they hug their label. The parent must use a stacked layout when full-width actions are expected. Minimum height is 44px, including the small variant.

<div class="actions">
  <button class="btn btn--primary" type="button">
    Explore destinations
  </button>
  <a class="btn btn--secondary" href="sites.html">Browse sites</a>
</div>

.actions { container: action-bar / inline-size;
  display:flex; flex-wrap:wrap; gap:.75rem; }
.btn { display:inline-flex; min-height:44px;
  align-items:center; justify-content:center; }
@container action-bar (max-width:26rem) {
  .btn:not(.btn--inline) { width:100%; }
}

States: hover, active, focus-visible and native disabled. Use disabled on unavailable buttons. aria-disabled alone does not stop a link activating; remove its navigation and implement disabled behaviour if that pattern is needed. Do not hide essential information in hover states.

Full source: styles/components.css, “ATOM 2”; live example: previews/atom-button.html.

Atom 02

Typography

Usage: style actual headings with .type-h1 through .type-h4; use body styles for descriptions and captions for attribution. Pick semantic heading levels according to document structure, not desired visual size. One main heading per page is the library convention.

Responsive logic: inside prose, ≤20rem changes h1 styling to the h2 token and h2 styling to the h3 token. At ≥45rem, paragraphs cap at 68ch. The shared type tokens also use viewport-fluid clamp(). No text is removed at a narrow width.

<section class="type-prose">
  <p class="type-eyebrow">Alaminos City</p>
  <h1 class="type-h1">Hundred Islands</h1>
  <p class="type-body">Plan a responsible coastal visit.</p>
</section>

.type-prose { container:prose / inline-size; }
.type-h1 { font-size:var(--fs-h1); }
@container prose (max-width:20rem) {
  .type-h1 { font-size:var(--fs-h2); }
  .type-h2 { font-size:var(--fs-h3); }
}
@container prose (min-width:45rem) {
  p { max-width:68ch; }
}

Accessibility: body copy is 1rem with 1.6 line height. Do not enforce fixed-height text containers. Retest at 200% zoom and with text-spacing overrides. The system-font fallback is deliberate: no font download is needed before visitors can read the page.

Full source: styles/tokens.css, typography tokens; styles/components.css, “ATOM 1”; live: previews/atom-typography.html.

Atom 03

Colour Tokens

Usage: tokens provide the shared colour vocabulary. Use --color-primary for primary controls, --color-accent for emphasis and --color-text-muted for secondary copy. Change the token layer to change the brand consistently; do not scatter new hex values through pages.

Responsive logic: the colour values themselves do not change with size. The documentation swatch component queries swatches: fewer than 30rem gives two columns; ≥30rem gives four; ≥45rem gives six. This distinction prevents an artificial “responsive colour” claim.

<div class="swatch-group"><div class="swatch-grid">
  <div class="swatch">
    <div class="swatch__chip" style="background:var(--color-primary)"></div>
    <div class="swatch__meta">
      <span class="swatch__name">Primary</span>
      <span class="swatch__value">#0E566A</span>
    </div>
  </div>
</div></div>
.swatch-group { container:swatches / inline-size; }
.swatch-grid { display:grid; grid-template-columns:repeat(2,1fr); }
@container swatches (min-width:30rem) {
  .swatch-grid { grid-template-columns:repeat(4,1fr); }
}
@container swatches (min-width:45rem) {
  .swatch-grid { grid-template-columns:repeat(6,1fr); }
}

Accessibility: never communicate selected state, errors or category meaning through colour alone. Use text and shape too. The light slate card border is decorative; inputs use a darker control border. Recalculate contrast whenever foreground or background aliases change.

Full source: styles/tokens.css and “ATOM 5” in components.css; live: previews/atom-color-tokens.html.

Atom 04

Icon

Usage: use an icon to reinforce an existing text label, such as a map pin beside a municipality. The included simple SVG path drawings are local UI code, not an external icon-font dependency. Do not replace an unfamiliar concept with an unexplained icon.

Responsive logic: fixed variants are 0.875rem, 1rem, 1.25rem and 1.75rem. .icon--adaptive changes from the 1rem default to 1.375rem when the nearest size container is ≥45rem. Below that, no special breakpoint applies.

<span>
  <svg class="icon icon--adaptive" viewBox="0 0 24 24"
       aria-hidden="true" focusable="false">
    <path d="M12 21s-7-5.6-7-11a7 7 0 1 1 14 0c0 5.4-7 11-7 11z"/>
    <circle cx="12" cy="10" r="2.5"/>
  </svg>
  Alaminos City
</span>
.icon { width:1rem; height:1rem; fill:none;
  stroke:currentColor; stroke-width:1.75; }
@container (min-width:45rem) {
  .icon--adaptive { width:1.375rem; height:1.375rem; }
}

Accessibility: decorative SVGs use aria-hidden="true". A standalone icon button needs an accessible name on the button, e.g. aria-label="Open navigation". Its hit area remains at least 44px even if the drawn icon is only 20px. Essential icon contrast is tested against its actual background.

Full source: components.css, “ATOM 3”; SVG symbol examples: previews/atom-icon.html.

Atom 05

Image / Media

Usage: wrap a site photograph and its caption in a semantic figure. Supply meaningful alt text when it communicates content, or alt="" when the image is truly redundant. Explicit dimensions and a reserved frame reduce layout movement.

Responsive logic: the figure named media queries its own content width to style its child frame: ≤20rem gives 4:3; above 20rem and below 45rem gives 16:9; ≥45rem gives 21:9. object-fit:cover crops without stretching.

<figure class="media">
  <div class="media__frame">
    <img class="media__img" src="images/islands-640.webp"
         width="640" height="400"
         alt="Small green islands surrounded by blue sea"
         loading="lazy" decoding="async">
  </div>
  <figcaption class="media__caption">Hundred Islands</figcaption>
</figure>
.media { container:media / inline-size; }
.media__frame { aspect-ratio:16/9; overflow:hidden; }
.media__img { width:100%; height:100%; object-fit:cover; }
@container media (max-width:20rem) {
  .media__frame { aspect-ratio:4/3; }
}
@container media (min-width:45rem) {
  .media__frame { aspect-ratio:21/9; }
}

Production note: the snippet's image filename is a replacement example, not a shipped optimized asset. The live example uses actual remote photos. Before release, create permitted 320/640/960px WebP or AVIF derivatives and add srcset/sizes. Do not lazy-load the page's primary above-the-fold hero. Card media overrides this atom's crop to 3:2 stacked and 4:3 horizontal.

Full source: “ATOM 4”; live: previews/atom-image.html. Image sources are listed in section 5.

Molecule 01

Heritage Card

Usage: display one destination preview inside a Heritage Grid or featured destination slot. Required data: site name, municipality, image and alt text, short summary and destination URL. Avoid unverified visitor ratings, prices and opening hours.

Responsive logic: wrapper card, ≤20rem hides the description and reduces title styling; the linked full detail page must retain the complete information. From >20rem to <32rem the card is stacked with a two-line summary. At ≥32rem it becomes horizontal with proportional 42:58 tracks after allowing for the gap.

<div class="card-container">
  <article class="heritage-card">
    <figure class="media heritage-card__media">
      <div class="media__frame"><img class="media__img"
        src="images/islands.webp" alt="Hundred Islands seascape"
        width="640" height="400"></div>
    </figure>
    <div class="heritage-card__body">
      <p class="heritage-card__place">Alaminos City</p>
      <h3 class="heritage-card__title">Hundred Islands</h3>
      <p class="heritage-card__desc">A coastal destination.</p>
      <a class="btn btn--secondary" href="sites/hundred-islands/">View Hundred Islands</a>
    </div>
  </article>
</div>
.card-container { container:card / inline-size; }
@container card (min-width:32rem) {
  .heritage-card { display:grid;
    grid-template-columns:minmax(0,.42fr) minmax(0,.58fr); }
}

This extract expects a real destination URL and image added by the integrator. The runnable preview uses labelled demonstration anchors. Full source: “MOLECULE 1”; live: previews/molecule-heritage-card.html.

Molecule 02

Search Form

Usage: allow a visitor to filter destination previews by phrase and category. The live example searches three sample entries locally; it does not claim a remote search API. Results include an announced count and an explicit zero-result state.

Responsive logic: search below 28rem stacks the field, filter and button. At ≥28rem the form becomes a horizontal row; the search field grows while the select and action retain useful widths. Never use placeholder text as the only label.

<div class="search-container">
  <form class="search-form" role="search" data-demo-search>
    <div class="search-form__field search-form__field--grow">
      <label for="q" class="search-form__label">Search sites</label>
      <input id="q" class="input" type="search" name="q">
    </div>
    <button class="btn" type="submit">Search sites</button>
  </form>
</div>
<p id="search-status" role="status" aria-live="polite"></p>
<ul><li data-site="hundred islands" data-category="nature">
  Hundred Islands
</li></ul>
.search-container { container:search / inline-size; }
.search-form { display:flex; flex-direction:column; }
@container search (min-width:28rem) {
  .search-form { flex-direction:row; align-items:flex-end; }
}

Behaviour contract: load demo.js for the local filter. Its demonstration handler expects result items with data-site and an element named search-status. Normalize data-site to lower case. Use unique input IDs if forms repeat. In Nuxt, replace the handler with reactive filtering and preserve labels, keyboard submission and polite announcements. Without JavaScript, keep all destination cards visible.

Full source: “MOLECULE 2” and demo.js; live: previews/molecule-search-form.html.

Molecule 03

Navigation Item

Usage: one destination inside a primary or secondary navigation group. It combines icon, label, optional helper and optional badge. Put aria-current="page" on the link for the current route; do not assign it to every link.

Responsive logic: the nav-item wrapper ≤9rem visually hides its label and badge without removing the accessible label. From >9rem to <16rem show icon and label. At ≥16rem add the helper. Avoid an icon-only layout when icons are unfamiliar; an integrator can keep labels visible instead.

<div class="nav-item">
  <a class="nav-item__link" href="destinations.html"
     aria-current="page">
    <svg class="icon nav-item__icon" viewBox="0 0 24 24"
         aria-hidden="true">
      <path d="M4 5h16v14H4z"/>
    </svg>
    <span class="nav-item__text">
      <span class="nav-item__label">Destinations</span>
      <span class="nav-item__desc">Explore the province</span>
    </span>
  </a>
</div>
.nav-item { container:nav-item / inline-size; }
@container nav-item (max-width:9rem) {
  .nav-item__label { position:absolute; width:1px; height:1px;
    overflow:hidden; clip-path:inset(50%); }
}
@container nav-item (min-width:16rem) {
  .nav-item__desc { display:block; }
}

Accessibility: current state uses an inset accent stripe and weight as well as colour. The anchor is keyboard-focusable and at least 44px high. Do not add role="menuitem" to ordinary website navigation links; retain familiar document navigation semantics.

Full source: “MOLECULE 3”; live: previews/molecule-navigation-item.html.

Organism 01

Heritage Grid

Usage: list related destinations in the main content region. The grid owns the number of columns; each child card owns its interior layout. This separation lets a card be reused in a full-width list and a narrow sidebar.

Responsive logic: query wrapper heritage-grid: below 40rem show one column; ≥40rem show two; ≥64rem show three. A wide grid does not force an individual card to be horizontal: the card sees its own allocated parent width.

<section aria-labelledby="sites-heading">
  <h2 id="sites-heading" class="type-h2">Heritage sites</h2>
  <div class="grid-container">
    <div class="heritage-grid">
      <!-- Repeat the complete card-container/article from Molecule 01. -->
    </div>
  </div>
</section>
.grid-container { container:heritage-grid / inline-size; }
.heritage-grid { display:grid; grid-template-columns:1fr;
  gap:var(--grid-gap); }
@container heritage-grid (min-width:40rem) {
  .heritage-grid { grid-template-columns:repeat(2,minmax(0,1fr)); }
}
@container heritage-grid (min-width:64rem) {
  .heritage-grid { grid-template-columns:repeat(3,minmax(0,1fr)); }
}

Content and accessibility: use a section heading and logical card headings. Keep source order equal to reading order; do not rearrange cards solely through CSS. Provide a meaningful empty-state paragraph if filtering removes all cards. Never lazy-load all above-the-fold images indiscriminately; load below-fold cards lazily.

Full source: “ORGANISM 1”; live: previews/organism-heritage-grid.html. The preview contains three complete cards; use those as copyable markup, not the placeholder comment above.

3. Build a new page using this library

  1. Copy the relevant complete markup from template/previews/; retain its named wrapper and classes.
  2. Load the three shared stylesheets in order. Use a real language attribute, page title, main landmark and heading hierarchy.
  3. Compose the header organism, a page introduction, the search molecule and the grid organism. Repeat the card molecule for each content record.
  4. Replace example URLs and image paths. Use distinct control IDs, correct current-page state and site-specific link labels.
  5. Integrate search and menu state in Vue/Nuxt if creating the proposed application. Do not run both a Vue state handler and demo.js on the same control.
  6. Test at just below, exactly at and just above each breakpoint. Add a screenshot and usage note whenever a component changes.

Nuxt adaptation

Keep atoms/molecules/organisms in similarly named component directories. Convert repeated HTML to Vue props with typed content, use keyed loops for destination cards and retain semantic markup. Read content during generation and pass it to components; avoid embedding content-fetching credentials in the client. The integration configuration example is in template/integration/. It is not a complete application.

Maintenance contract

Change tokens before overriding individual component styles. Keep class names stable, document breaking changes, validate required content fields and review destination information. Do not add fee, booking, accessibility-facility or review claims without reliable sources and current confirmation.

4. Verification and submission checklist

Checks executed for this package

Chromium rendered all ten live examples and produced the included screenshots. Targeted local assertions checked card, search, navigation, grid and header breakpoint behaviour, search matches and zero results, menu open/close, Escape focus restoration, minimum small-button height and the narrow image crop. These are component-level checks only. No production Nuxt build, deployed GitHub site, Lighthouse score, axe scan, physical-device test or complete screen-reader audit is claimed.

Before claiming WCAG 2.1 AA on the full site

  • Run an automated accessibility scan; resolve all relevant violations and manually inspect anything the scanner cannot decide.
  • Use only Tab, Shift+Tab, Enter, Space and Escape. Confirm visible focus, logical order, no keyboard traps and working disclosure state.
  • Check complete pages at 320 CSS pixels and at 200% zoom; test 400% reflow conditions appropriately. Ensure no loss of information or unnecessary horizontal scrolling.
  • Test alt text, headings, landmarks, form labels and result announcements with a screen reader. Verify site-specific link names remain understandable.
  • Audit actual foreground/background pairs and every essential control state. Test user text-spacing overrides and reduced-motion settings.
  • Confirm responsive image sizing, copyright permission, broken-link handling and deep-link refresh after static deployment.

WCAG requirements apply to complete pages and processes; the library alone is insufficient to claim conformance. Use the W3C criteria as the authoritative reference. [3]

MIT-level rationale in plain language

Reusable design is not just visual consistency. A shared token can fix contrast everywhere; a card molecule can carry an accessible destination pattern across pages; an organism can change layout without changing content. Container queries make this reuse depend on available space rather than a guessed device type. The architectural value is reduced coupling: content, presentation, interaction and hosting can evolve with fewer unintended effects.
